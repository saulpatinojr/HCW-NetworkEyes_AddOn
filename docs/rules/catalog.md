## Texts

### AZ-BCDR-001 Azure Firewall is not zone-redundant

A single-zone firewall has no SLA protection against zonal failure; every flow routed through it is interrupted by a zone outage.

Remediation: Redeploy the firewall with zones=[1,2,3] and zone-redundant public IPs. A zonal outage would otherwise interrupt all inspected traffic.

Evidence: firewalls[].zones. Applies to: export.

### AZ-BCDR-002 VPN gateway runs in active-passive mode

Active-passive VPN gateways interrupt hybrid connectivity during failover and planned maintenance.

Remediation: Enable active-active mode (requires a second public IP and VpnGw2+ SKU) and BGP for automatic failover. Active-standby failover interrupts tunnels for up to 90 seconds on unplanned events.

Evidence: virtual_network_gateways[].active_active (gateway_type Vpn). Applies to: export.

### AZ-BCDR-003 Single ExpressRoute gateway terminates all circuit connectivity

All ExpressRoute private connectivity depends on a single gateway — a regional or gateway-level failure severs hybrid connectivity.

Remediation: Deploy a second ExpressRoute gateway in another region (or a zone-redundant SKU plus VPN failover) so a gateway failure does not sever all on-premises connectivity.

Evidence: express_route_circuits[], virtual_network_gateways[gateway_type=ExpressRoute]. Applies to: export.

### AZ-BCDR-004 Azure Firewall is a single point of failure for the tenant footprint

If spoke traffic is force-tunneled through one firewall, a firewall outage halts east-west and internet-bound traffic for the entire footprint.

Remediation: Deploy the firewall zone-redundant (zones=[1,2,3]) and define a documented bypass/failover runbook. For multi-region footprints, evaluate a secured-hub-per-region design (Azure Firewall in each regional hub or vWAN secured hubs).

Evidence: firewalls[] and vnets[] across every unblocked subscription. Applies to: export.

### AZ-BCDR-005 Virtual network gateway is not zone-redundant

A zonal failure would take down all tunnels/circuit connectivity terminating on this gateway.

Remediation: Migrate to an AZ SKU (e.g. VpnGw2AZ / ErGw2AZ) deployed with zones=[1,2,3] and zone-redundant public IPs.

Evidence: virtual_network_gateways[].zones (non-Basic SKUs). Applies to: export.

### AZ-BCDR-006 Application Gateway is not zone-redundant

A zonal outage interrupts every listener on a gateway that is not spread across zones.

Remediation: Redeploy the v2 gateway with zones=[1,2,3] and a zone-redundant Standard public IP for its frontend.

Evidence: application_gateways[].zones (v2 SKUs). Applies to: export.

### AZ-BCDR-007 Standard load balancer is not zone-redundant

A zonal outage takes the frontend with it when it is pinned to one zone or to none.

Remediation: Configure the frontend IP as zone-redundant (zones=[1,2,3]) and spread the backend pool across zones.

Evidence: load_balancers[].zones (Standard SKU). Applies to: export.

### AZ-COST-001 Orphaned public IP incurs charges with no workload

A public IP is billed while unattached.

Remediation: Delete the unassociated public IP if no longer needed, or document the reservation intent in resource tags. Use Azure Policy to alert on orphaned public IPs.

Evidence: public_ips[].associated_resource_type. Applies to: export.

### AZ-COST-002 Gateway billed but moved zero traffic in 24 hours

An idle gateway continues to accrue hourly charges.

Remediation: Confirm the gateway is still required. If its tunnels are unused, decommission the gateway and its public IPs; if traffic belongs on them, investigate tunnel and routing health.

Evidence: network_metrics.gateway_metrics[].ingress_bytes_24h / egress_bytes_24h. Applies to: live-only.

### AZ-COST-003 VPN gateway SKU is oversized for observed traffic

A smaller SKU on the same ladder serves the observed peak.

Remediation: Resize the VPN gateway to the next smaller SKU on the same ladder after reviewing 30 days of utilisation and planned growth; the resize interrupts connectivity briefly, so schedule a window.

Evidence: network_metrics.gateway_metrics[].utilization_pct (gateway_type Vpn). Applies to: live-only.

### AZ-COST-004 NAT gateway has no associated subnets

An unattached NAT gateway is billed hourly while providing no egress path.

Remediation: Associate the NAT gateway with the subnets that need predictable outbound SNAT, or delete it (and its public IPs) if it is no longer required.

Evidence: nat_gateways[].associated_subnet_ids. Applies to: export.

### AZ-COST-005 Azure Firewall billed while processing zero traffic

A deployed firewall accrues hourly charges regardless of traffic.

Remediation: Verify routing actually sends traffic through this firewall (see AZ-NET-009). If the firewall is genuinely unused, decommission it; if it protects intermittent workloads, consider Firewall Basic or stop/start automation.

Evidence: network_metrics.firewall_metrics[] rule hit counters. Applies to: live-only.

### AZ-NET-001 VNet does not have DDoS Protection enabled

The VNet has no DDoS Protection plan attached, so its public endpoints get only the platform's basic infrastructure protection.

Remediation: Attach a DDoS Network Protection plan to the VNet, or enable DDoS IP Protection on the public IPs that face the internet.

Evidence: vnets[].ddos_protection_enabled. Applies to: export.

### AZ-NET-002 Subnet has no Network Security Group

The subnet has no network security group, so nothing filters the traffic into or out of the workloads on it.

Remediation: Create a network security group with deny-by-default rules and associate it with the subnet, or with every network interface on it.

Evidence: vnets[].subnets[].nsg_id. Applies to: export.

### AZ-NET-003 Azure Firewall Threat Intelligence mode is not set to Deny

The firewall's threat intelligence mode is Alert or Off, so traffic to and from known malicious IP addresses and domains is logged or ignored, not blocked.

Remediation: Set threat intelligence to Deny on the firewall policy (or on the firewall itself when no policy is linked), after reviewing the alert log for allowlist entries.
