## Texts

### AZ-BCDR-001 Azure Firewall is not zone-redundant

A single-zone firewall has no protection against a zonal failure; every flow routed through it stops during a zone outage.

Remediation: Redeploy the firewall with zones [1, 2, 3] and zone-redundant public IPs.

Evidence: azurefirewalls zones count below 2. Applies to: export.

### AZ-BCDR-002 VPN gateway runs in active-passive mode

Active-passive gateways interrupt tunnels during failover and planned maintenance.

Remediation: Enable active-active mode (a second public IP and a VpnGw2 or higher SKU) and BGP for automatic failover.

Evidence: virtualnetworkgateways gatewayType Vpn with activeActive false. Applies to: export.

### AZ-BCDR-003 Single ExpressRoute gateway terminates all circuit connectivity

All ExpressRoute private connectivity depends on one gateway.

Remediation: Deploy a second ExpressRoute gateway in another region, or a zone-redundant SKU plus a VPN failover path.

Evidence: expressroutecircuits present and exactly one virtualnetworkgateways row with gatewayType ExpressRoute. Applies to: export.

### AZ-BCDR-004 One Azure Firewall is a single point of failure for the whole footprint

When spoke traffic is force-tunnelled through one firewall, a firewall outage halts east-west and internet-bound traffic for every VNet.

Remediation: Deploy the firewall zone-redundant with a recorded bypass runbook; for multi-region footprints, one secured hub per region.

Evidence: exactly one azurefirewalls row across the export and more than one VNet. Applies to: export.

### AZ-BCDR-005 Virtual network gateway is not zone-redundant

A zonal failure takes down every tunnel or circuit terminating on this gateway.

Remediation: Migrate to an AZ SKU (VpnGw2AZ, ErGw2AZ or higher) deployed with zones [1, 2, 3] and zone-redundant public IPs.

Evidence: virtualnetworkgateways (non-Basic SKU) zones count below 2. Applies to: export.

### AZ-BCDR-006 Application Gateway v2 is not zone-redundant

A gateway in fewer than two zones is a single point of failure for the ingress it fronts.

Remediation: Redeploy the gateway with zones [1, 2, 3] and a zone-redundant Standard public IP.

Evidence: applicationgateways v2 SKU with zones count below 2. Applies to: export.

### AZ-BCDR-007 Standard load balancer frontend is not zone-redundant

A zonal frontend stops serving when its zone fails.

Remediation: Configure the frontend IP as zone-redundant (zones [1, 2, 3]) and spread the backend across zones.

Evidence: loadbalancers Standard SKU whose frontendIPConfigurations carry fewer than 2 zones. Applies to: export.

### AZ-COST-001 Orphaned public IP incurs charges with no workload

A public IP is billed while unattached.

Remediation: Delete the unassociated public IP if it is no longer needed, or record the reservation intent in a tag; an Azure Policy alert catches new orphans.

Evidence: publicipaddresses with no properties.ipConfiguration. Applies to: export.

### AZ-COST-002 Gateway is billed but moved zero traffic in 24 hours

An idle gateway accrues hourly charges.

Remediation: Confirm the gateway is still required; decommission unused gateways and their public IPs.

Evidence: Azure Monitor TunnelIngressBytes and TunnelEgressBytes over 24 hours. Applies to: live-only (count-based; works without a properties column).

### AZ-COST-003 VPN gateway SKU is oversized for the observed traffic

A gateway peaking far below its ceiling is paid for capacity it does not use.

Remediation: Resize to the next smaller SKU after reviewing a 30-day window and planned growth.

Evidence: Azure Monitor AverageBandwidth over 24 hours against the SKU ceiling (below 10 percent). Applies to: live-only (count-based; works without a properties column).

### AZ-COST-004 NAT gateway has no associated subnets

An unattached NAT gateway is billed hourly while providing no egress path.

Remediation: Associate the NAT gateway with the subnets that need predictable outbound SNAT, or delete it and its public IPs.

Evidence: natgateways with an empty properties.subnets list. Applies to: export.

### AZ-COST-005 Azure Firewall is billed while processing zero traffic

A deployed firewall accrues hourly charges regardless of traffic.

Remediation: Confirm routing sends traffic through the firewall; decommission it if it is unused, or use Firewall Basic for intermittent workloads.

Evidence: Azure Monitor rule-hit metrics over 24 hours (cost angle of AZ-NET-009). Applies to: live-only (count-based; works without a properties column).

### AZ-NET-001 VNet does not have DDoS Protection enabled

The VNet is not protected by a DDoS Network Protection plan; it relies on the platform's infrastructure protection only.

Remediation: Attach a DDoS Network Protection plan to VNets that host public-facing workloads, in particular those with application gateways or public IPs.

Evidence: virtualnetworks properties.enableDdosProtection. Applies to: export.

### AZ-NET-002 Subnet has no Network Security Group

Every workload subnet carries an NSG; GatewaySubnet, AzureFirewallSubnet, AzureFirewallManagementSubnet and RouteServerSubnet are platform subnets and are skipped.

Remediation: Attach an NSG with least-privilege inbound rules: deny by default, permit only the required ports from approved sources.

Evidence: virtualnetworks properties.subnets[].properties.networkSecurityGroup (platform subnets skipped). Applies to: export.

### AZ-NET-003 Azure Firewall Threat Intelligence mode is not set to Deny

Known malicious IPs and domains are alerted on but not blocked.

Remediation: Set Threat Intelligence to Deny in the firewall policy after reviewing the alert logs for legitimate traffic.
